# Θεωρία ουρών

Η θεωρία ουρών, γνωστή και ως θεωρία ουρών αναμονής, είναι η μαθηματική μελέτη
των γραμμών αναμονής, δηλαδή των ουρών. Χρησιμοποιούμε τη θεωρία ουρών στην
ανάπτυξη λογισμικού για σκοπούς όπως η ανάλυση και η βελτιστοποίηση των
πρακτικών και των διαδικασιών μας, για παράδειγμα την ταχύτητα απόκρισης της
εξυπηρέτησης πελατών, τον σχεδιασμό kanban στη διαχείριση έργων, τις ουρές
μηνυμάτων για επικοινωνία μεταξύ διεργασιών και τις γραμμές συνεχούς ανάπτυξης
(pipelines) στο DevOps.

## Εισαγωγή

Χρησιμοποιούμε τη θεωρία ουρών στα έργα μας για πολλούς σκοπούς:

- Ταχύτητα απόκρισης της εξυπηρέτησης πελατών

- Σχεδιασμός kanban στη διαχείριση έργων

- Ουρές μηνυμάτων για επικοινωνία μεταξύ διεργασιών

- Γραμμές συνεχούς ανάπτυξης στο DevOps

### Ταχύτητα απόκρισης της εξυπηρέτησης πελατών

Για παράδειγμα, θέλουμε να αναλύσουμε πώς οι πελάτες ζητούν βοήθεια για πωλήσεις και υποστήριξη, και πόσο γρήγορα ανταποκρινόμαστε.

Ορισμένα σχετικά προϊόντα είναι π.χ. [Salesforce](https://wikipedia.org/wiki/Salesforce), [LiveChat](https://wikipedia.org/wiki/LiveChat), [Zendesk](https://wikipedia.org/wiki/Zendesk).

### Σχεδιασμός kanban στη διαχείριση έργων

Για παράδειγμα, θέλουμε να παρακολουθούμε τους χρόνους παράδοσης και τους χρόνους προόδου καθώς μια ιδέα για νέα λειτουργία εξελίσσεται από τον σχεδιασμό μέχρι την παράδοση.

Ορισμένα σχετικά προϊόντα είναι π.χ. [Asana](<https://wikipedia.org/wiki/Asana_(software)>), [Jira](<https://wikipedia.org/wiki/Jira_(software)>), [Microsoft Project](https://wikipedia.org/wiki/Microsoft_Project).

### Ουρές μηνυμάτων για επικοινωνία μεταξύ διεργασιών

Για παράδειγμα, θέλουμε να μεγιστοποιήσουμε τη διεκπεραίωση και να ελαχιστοποιήσουμε τις πιέσεις όταν ένα πρόγραμμα στέλνει αιτήματα σε ένα άλλο πρόγραμμα.

Ορισμένα σχετικά προϊόντα είναι π.χ. [RabbitMQ](https://wikipedia.org/wiki/RabbitMQ), [ActiveMQ](https://wikipedia.org/wiki/Apache_ActiveMQ), [ZeroMQ](https://wikipedia.org/wiki/ZeroMQ).

### Γραμμές συνεχούς ανάπτυξης στο DevOps

Για παράδειγμα, θέλουμε να διασφαλίσουμε ότι ο διακομιστής συνεχούς ενοποίησης έχει την ικανότητα να ελέγχει το λογισμικό μας και στη συνέχεια να το αναπτύσσει.

Ορισμένα σχετικά προϊόντα είναι π.χ. [Jenkins](<https://wikipedia.org/wiki/Jenkins_(software)>), [Bamboo](<https://wikipedia.org/wiki/Bamboo_(software)>), [Azure DevOps](https://wikipedia.org/wiki/Microsoft_Visual_Studio#Azure_DevOps).

## Ορολογία ουρών

Η ορολογία των ουρών είναι ένα μεγάλο θέμα. Αυτή η ενότητα περιέχει μέρος της κοινής μας ορολογίας. Στα παραδείγματα θα χρησιμοποιούμε την ιδέα ενός πελάτη που περιμένει στη σειρά.

### Τύποι ουρών και τύποι εξυπηρέτησης

Οι τύποι ουρών και οι τύποι εξυπηρέτησης περιγράφουν πώς η ουρά επιλέγει ποια στοιχεία θα επεξεργαστεί.

- Πρώτος μέσα, πρώτος έξω (FIFO): εξυπηρετείται ο πελάτης που περιμένει τον περισσότερο χρόνο.

- Τελευταίος μέσα, πρώτος έξω (LIFO): εξυπηρετείται ο πελάτης που περιμένει τον λιγότερο χρόνο.

- Προτεραιότητα: οι πελάτες εξυπηρετούνται ανάλογα με το επίπεδο προτεραιότητάς τους· τα επίπεδα αυτά μπορεί να βασίζονται στην ιδιότητα, στον επείγοντα χαρακτήρα, στην πληρωμή κ.λπ.

- Πρώτα η συντομότερη εργασία (SJF): εξυπηρετείται ο πελάτης που χρειάζεται τη μικρότερη ποσότητα εξυπηρέτησης.

- Πρώτα η μακρύτερη εργασία (LJF): εξυπηρετείται ο πελάτης που χρειάζεται τη μεγαλύτερη ποσότητα εξυπηρέτησης.

- Συντομότερος υπολειπόμενος χρόνος επεξεργασίας (SRPT): όπως το SJF, αλλά μια σύντομη εργασία που μόλις έφτασε μπορεί να διακόψει μια μακρύτερη εργασία που ήδη εξυπηρετείται.

- Κυκλική εναλλαγή (Round Robin): κάθε πελάτης εξυπηρετείται για ένα σύντομο χρονικό διάστημα, στη συνέχεια η εξυπηρέτηση περνά στον επόμενο πελάτη, και η διαδικασία επαναλαμβάνεται.

- Καταμερισμός χρόνου, γνωστός και ως καταμερισμός επεξεργαστή (PS): όλοι εξυπηρετούνται ταυτόχρονα· η ικανότητα εξυπηρέτησης κατανέμεται ισομερώς σε όλους όσοι περιμένουν.

Τα SJF και SRPT ελαχιστοποιούν τη μέση αναμονή, αλλά μπορεί να αφήνουν τις μακριές εργασίες να περιμένουν επ' αόριστον, γι' αυτό τα πραγματικά συστήματα συχνά προσθέτουν γήρανση (aging) ή ανώτατα όρια προτεραιότητας.

## Συμβολισμός της θεωρίας ουρών

Η θεωρία ουρών χρησιμοποιεί συμβολισμό με ελληνικά γράμματα.

Οι ομάδες μας χρησιμοποιούν μέρος του δημοφιλούς συμβολισμού· προσθέτουμε επίσης ορισμένα δικά μας σύμβολα που μας βοηθούν στα έργα λογισμικού.

Ο δικός μας συμβολισμός και τι σημαίνει κάθε σύμβολο:

| Ο δικός μας συμβολισμός | Σημασία |
| ----------------------- | ------- |
| κ (κάπα) | αριθμός στοιχείων στο σύστημα, σε αναμονή και υπό επεξεργασία |
| λ (λάμδα) | ρυθμός αφίξεων των στοιχείων που εισέρχονται στο σύστημα |
| χ (χι) | ρυθμός αναχωρήσεων των στοιχείων που εξέρχονται από το σύστημα |
| μ (μι) | ρυθμός εξυπηρέτησης, γνωστός και ως ικανότητα: πόσο γρήγορα εργάζεται ένας εξυπηρετητής όταν είναι απασχολημένος |
| ρ (ρο) | χρησιμοποίηση: το ποσοστό του χρόνου που οι εξυπηρετητές είναι απασχολημένοι, λ / (c μ) |
| α (άλφα) | ρυθμός επιτυχίας: παρατηρούμενη έξοδος που αποδεικνύεται σωστή |
| β (βήτα) | ρυθμός αποτυχίας: παρατηρούμενη έξοδος που αποδεικνύεται λανθασμένη |
| δ (δέλτα) | ρυθμός ολοκλήρωσης: επιτυχία + αποτυχία, στοιχεία που εξυπηρετήθηκαν με σωστό ή λάθος αποτέλεσμα |
| σ (σίγμα) | ρυθμός παράλειψης: στοιχεία που εισήλθαν και αποχώρησαν χωρίς εξυπηρέτηση |
| ε (έψιλον) | λόγος σφαλμάτων: β / δ = β / (α + β) |
| τ (ταυ) | χρόνος στο σύστημα, γνωστός και ως χρόνος παράδοσης |
| ω (ωμέγα) | χρόνος αναμονής, γνωστός και ως χρόνος στην ουρά |
| φ (φι) | χρόνος εργασίας, γνωστός και ως χρόνος στον επεξεργαστή, γνωστός και ως χρόνος εξυπηρέτησης |
| θ (θήτα) | χρόνος βήματος μεταξύ ολοκληρώσεων· μέσος χρόνος βήματος ≈ 1 / χ σε σταθερή κατάσταση |

### Πλήθος

Μετράμε συχνά στοιχεία και χρησιμοποιούμε αυτόν τον συμβολισμό:

- κ (κάπα): πλήθος στοιχείων στο σύστημα, δηλαδή στοιχεία σε αναμονή συν στοιχεία υπό επεξεργασία.

![Διάγραμμα: κ στοιχεία βρίσκονται στο σύστημα](https://queue-theory.github.io/images/queue-theory-kappa-item-count.svg)

Παράδειγμα:

- κ = 10 σημαίνει ακριβώς 10

- κ ≈ 10 σημαίνει περίπου 10

- κ < 10 σημαίνει λιγότερο από 10

- κ > 10 σημαίνει περισσότερο από 10

- κ ≪ 10 σημαίνει πολύ λιγότερο από 10

- κ ≫ 10 σημαίνει πολύ περισσότερο από 10

Το πλήθος κ (κάπα) είναι ένα στιγμιότυπο σε μια δεδομένη στιγμή.

Το μέσο πλήθος κ̅ (κάπα με παύλα) είναι ένας υπολογισμός που βγάζει τον μέσο όρο μετρήσεων σε μια συγκεκριμένη χρονική περίοδο, όπως μέτρηση κάθε ώρα επί δύο εβδομάδες.

### Ρυθμός αφίξεων, ρυθμός εξυπηρέτησης, ρυθμός αναχωρήσεων

Ο πιο σημαντικός συμβολισμός:

- λ (λάμδα): ρυθμός αφίξεων. Μετρά πόσο γρήγορα τα στοιχεία εισέρχονται στο σύστημα.

- μ (μι): ρυθμός εξυπηρέτησης, γνωστός και ως ικανότητα. Μετρά πόσο γρήγορα ένας εξυπηρετητής μπορεί να χειριστεί στοιχεία όταν είναι απασχολημένος.

- χ (χι): ρυθμός αναχωρήσεων. Μετρά πόσο γρήγορα τα στοιχεία εξέρχονται από το σύστημα.

![Διάγραμμα: τα στοιχεία φτάνουν με ρυθμό λ, εξυπηρετούνται με ρυθμό μ και αναχωρούν με ρυθμό χ](https://queue-theory.github.io/images/queue-theory-lambda-arrival-mu-service-chi-departure.svg)

Παραδείγματα γενικών κανόνων για παραδοσιακές ουρές με έναν εξυπηρετητή:

- λ < μ σημαίνει ότι ο ρυθμός αφίξεων είναι μικρότερος από τον ρυθμό εξυπηρέτησης· η ουρά είναι σταθερή, δηλαδή κυμαίνεται γύρω από ένα πεπερασμένο μέσο μέγεθος.

- λ = μ σημαίνει ότι ο ρυθμός αφίξεων ισούται με τον ρυθμό εξυπηρέτησης· με οποιαδήποτε τυχαιότητα, η ουρά μετατοπίζεται και μεγαλώνει χωρίς όριο.

- λ > μ σημαίνει ότι ο ρυθμός αφίξεων είναι μεγαλύτερος από τον ρυθμό εξυπηρέτησης· η ουρά μεγαλώνει σταθερά, κατά περίπου λ − μ στοιχεία ανά μονάδα χρόνου.

Η διαισθητική ιδέα ότι «λ = μ διατηρεί την ουρά στο ίδιο μέγεθος» ισχύει μόνο όταν οι αφίξεις και η εξυπηρέτηση είναι απόλυτα κανονικές, όπως ένας μετρονόμος. Οι πραγματικές αφίξεις έρχονται σε ριπές, οπότε ο αδρανής χρόνος που χάνεται σε μια περίοδο ηρεμίας δεν μπορεί ποτέ να ανακτηθεί, και η ουρά μεγαλώνει κατά την επόμενη ριπή.

Λάβετε υπόψη ότι ορισμένοι επαγγελματίες της θεωρίας ουρών χρησιμοποιούν τον όρο «ρυθμός εξυπηρέτησης» με την έννοια της παρατηρούμενης εξόδου αντί της ικανότητας· δείτε [αποσαφήνιση του ρυθμού εξυπηρέτησης](#αποσαφήνιση-του-ρυθμού-εξυπηρέτησης).

### Λόγος χρησιμοποίησης ή ένταση κυκλοφορίας

Ο πιο σημαντικός συμβολισμός που συνοψίζει μια ουρά:

- ρ (ρο): λόγος χρησιμοποίησης, δηλαδή το ποσοστό του χρόνου που οι εξυπηρετητές είναι απασχολημένοι = λ / μ για έναν εξυπηρετητή, ή λ / (c μ) για c εξυπηρετητές

Παραδείγματα:

- ρ < 1 σημαίνει ότι οι εξυπηρετητές έχουν διαθέσιμη ικανότητα· η ουρά είναι σταθερή. Όσο πιο κοντά φτάνει το ρ στο 1, τόσο μεγαλύτερες είναι οι αναμονές· δείτε [την καμπύλη χρησιμοποίησης](#η-καμπύλη-χρησιμοποίησης).

- ρ = 1 σημαίνει ότι οι εξυπηρετητές είναι απασχολημένοι συνεχώς· η ουρά είναι ασταθής και μεγαλώνει χωρίς όριο.

- ρ > 1 σημαίνει ότι οι αφίξεις υπερβαίνουν την ικανότητα· η ουρά μεγαλώνει.

### Ρυθμοί διεκπεραίωσης: ρυθμός αναχωρήσεων, ρυθμός ολοκλήρωσης, ρυθμός επιτυχίας, ρυθμός αποτυχίας, ρυθμός παράλειψης

Οι ρυθμοί διεκπεραίωσης μετρούν την παρατηρούμενη έξοδο, δηλαδή τα στοιχεία που πράγματι εξέρχονται από την ουρά. Χωρίζονται σε πέντε γενικές κατηγορίες:

- χ (χι): ρυθμός αναχωρήσεων. Μετρά πόσο γρήγορα τα στοιχεία εξέρχονται από το σύστημα.

- α (άλφα): ρυθμός επιτυχίας. Μετρά πόσα στοιχεία ανά χρονική περίοδο αποδεικνύονται σωστά, π.χ. ορθά, πλήρη, αποδεκτά.

- β (βήτα): ρυθμός αποτυχίας. Μετρά πόσα στοιχεία ανά χρονική περίοδο αποδεικνύονται λανθασμένα, π.χ. εσφαλμένα, ελλιπή, απορριφθέντα.

- δ (δέλτα): ρυθμός ολοκλήρωσης. Μετρά πόσα στοιχεία ανά χρονική περίοδο εξυπηρετούνται.

- σ (σίγμα): ρυθμός παράλειψης. Μετρά πόσα στοιχεία ανά χρονική περίοδο εισέρχονται στην ουρά και στη συνέχεια αποχωρούν χωρίς να εξυπηρετηθούν, π.χ. εγκαταλείψεις, αποχωρήσεις λόγω αναμονής.

![Διάγραμμα: ρυθμός αναχωρήσεων χ = ρυθμός ολοκλήρωσης δ + ρυθμός παράλειψης σ; ρυθμός ολοκλήρωσης δ = ρυθμός επιτυχίας α + ρυθμός αποτυχίας β](https://queue-theory.github.io/images/queue-theory-chi-departure-delta-done-alpha-success-beta-failure-sigma-skip.svg)

Ρυθμός ολοκλήρωσης = ρυθμός επιτυχίας + ρυθμός αποτυχίας:

- δ = α + β (προφέρεται: δέλτα ίσον άλφα συν βήτα)

Συνολικός ρυθμός = ρυθμός ολοκλήρωσης + ρυθμός παράλειψης:

- χ = δ + σ (προφέρεται: χι ίσον δέλτα συν σίγμα)

Συνολικός ρυθμός = ρυθμός επιτυχίας + ρυθμός αποτυχίας + ρυθμός παράλειψης:

- χ = α + β + σ (προφέρεται: χι ίσον άλφα συν βήτα συν σίγμα)

Κάθε στοιχείο που μετράται στο χ εισήλθε στο σύστημα, επομένως σε σταθερή κατάσταση ο συνολικός ρυθμός ισούται με τον ρυθμό αφίξεων: χ ≈ λ. Γι' αυτό οι ρυθμοί διεκπεραίωσης μετρούν την έξοδο και όχι την ικανότητα.

### Αποσαφήνιση του ρυθμού εξυπηρέτησης

Ανάλογα με το πλαίσιο και τον επαγγελματία, ο όρος «ρυθμός εξυπηρέτησης» μπορεί να σημαίνει είτε
«συνολικό ρυθμό» είτε «ρυθμό επιτυχίας».

Αυτό έχει ιστορικές ρίζες και μπορεί να οδηγήσει σε σύγχυση και λάθη, ιδίως σε
πλαίσια και για επαγγελματίες που χρησιμοποιούν τη θεωρία ουρών όπου υπάρχει
σημαντική ανάγκη παρακολούθησης αποτυχιών και παραλείψεων.

- Θεωρητική οπτική: Ο ρυθμός εξυπηρέτησης είναι καθαρή μέτρηση ταχύτητας (π.χ. εργασίες ανά δευτερόλεπτο), ανεξάρτητα από το αν οι εργασίες είναι επιτυχίες, αποτυχίες, παραλείψεις κ.λπ.

- Οπτική επεξεργασίας: Ο ρυθμός εξυπηρέτησης περιλαμβάνει ό,τι η ουρά αφιερώνει χρόνο να επεξεργαστεί, δηλαδή επιτυχίες ή αποτυχίες, αλλά δεν περιλαμβάνει παραλείψεις.

- Τεχνολογική οπτική: Σε εφαρμοσμένα πεδία όπως η μηχανική λογισμικού, ο ρυθμός εξυπηρέτησης μετρά μόνο επιτυχίες, ενώ ο ρυθμός σφαλμάτων μετρά αποτυχίες και ο ρυθμός παράλειψης μετρά παραλείψεις.

Γι' αυτό κρατάμε το μ για την ικανότητα και προσθέτουμε δίπλα του ρυθμούς παρατηρούμενης εξόδου, αντί να το αντικαταστήσουμε:

- μ (μι): ρυθμός εξυπηρέτησης, γνωστός και ως ικανότητα. Μετρά πόσο γρήγορα ένας εξυπηρετητής μπορεί να χειριστεί στοιχεία όταν είναι απασχολημένος.

- χ (χι): ρυθμός αναχωρήσεων. Μετρά πόσο γρήγορα τα στοιχεία εξέρχονται από το σύστημα.

- α (άλφα): ρυθμός επιτυχίας. Μετρά πόσα στοιχεία ανά χρονική περίοδο αποδεικνύονται σωστά, π.χ. ορθά, πλήρη, αποδεκτά.

Γιατί να μην αντικαταστήσουμε το μ με το χ ή το α; Σε μια σταθερή ουρά, κάθε στοιχείο που εισέρχεται τελικά αποχωρεί, επομένως χ ≈ λ. Τότε λ / χ ≈ 1 όποιο κι αν είναι το φορτίο, κάτι που δεν λέει τίποτα για το πόσο απασχολημένοι είναι οι εξυπηρετητές. Η χρησιμοποίηση χρειάζεται την ικανότητα: ρ = λ / (c μ), που ισούται με το ποσοστό του χρόνου που οι εξυπηρετητές είναι απασχολημένοι.

### Ρυθμός παράλειψης

Λεπτομέρειες για τον ρυθμό παράλειψης:

- σ (σίγμα): ρυθμός παράλειψης. Μετρά πόσα στοιχεία εισέρχονται στην ουρά και στη συνέχεια αποχωρούν χωρίς επεξεργασία.

Παράλειψη έχουμε όταν ένα στοιχείο εισέρχεται στην ουρά και στη συνέχεια αποχωρεί χωρίς ουσιαστική επεξεργασία:

- Εγκατάλειψη (abandoning): όταν ένας πελάτης μπαίνει σε μια ουρά και στη συνέχεια φεύγει, για οποιονδήποτε λόγο.

- Αποχώρηση λόγω αναμονής (reneging): όταν ένας πελάτης που έχει ήδη περιμένει αποφασίζει να φύγει επειδή έχει χάσει πάρα πολύ χρόνο.

Δύο σχετικές συμπεριφορές δεν αποτελούν παραλείψεις:

- Αποθάρρυνση (balking): όταν ένας πελάτης αποφασίζει να μην μπει στην ουρά επειδή ο χρόνος αναμονής απειλεί να είναι πολύ μεγάλος. Ένα στοιχείο που αποθαρρύνθηκε δεν εισέρχεται ποτέ στο σύστημα, επομένως βρίσκεται εκτός των ορίων του συστήματος: δεν μετράται στα λ, χ ή σ. Αν οι αποθαρρύνσεις έχουν σημασία, όπως οι χαμένες πωλήσεις, τότε μετρήστε τις χωριστά ως αφίξεις που απορρίφθηκαν.

- Μεταπήδηση (jockeying): όταν ένας πελάτης αλλάζει μεταξύ παράλληλων ουρών, όπως τα ταμεία, προσπαθώντας να βρει μικρότερη αναμονή.

### Λόγος σφαλμάτων

Ο πιο σημαντικός συμβολισμός που συνοψίζει την επιτυχία μιας ουράς:

- ε (έψιλον): λόγος σφαλμάτων = πλήθος αποτυχιών / πλήθος ολοκληρωμένων = β / δ = β / (α + β)

Οι παραλείψεις εξαιρούνται, επειδή ένα στοιχείο που παραλείφθηκε δεν εξυπηρετήθηκε ποτέ, άρα δεν ήταν ούτε σωστό ούτε λανθασμένο. Παρακολουθήστε τις παραλείψεις χωριστά μέσω του σ.

![Διάγραμμα: ο λόγος σφαλμάτων ε είναι ο ρυθμός αποτυχίας β διά του ρυθμού ολοκλήρωσης δ](https://queue-theory.github.io/images/queue-theory-delta-done-alpha-success-beta-failure-epsilon-error.svg)

Παραδείγματα:

- ε = 0 σημαίνει ότι δεν υπάρχουν σφάλματα.

- ε = 0,1 σημαίνει ότι το 10% των εξυπηρετήσεων έχει σφάλμα.

- ε = 1 σημαίνει ότι κάθε εξυπηρέτηση έχει σφάλμα.

### Χρόνος παράδοσης, χρόνος αναμονής, χρόνος εργασίας, χρόνος βήματος

Παρακολουθούμε τέσσερις χρόνους:

- τ (ταυ): χρόνος στο σύστημα, γνωστός και ως χρόνος παράδοσης, γνωστός και ως από την αρχή μέχρι το τέλος.

- θ (θήτα): χρόνος βήματος = από μία ολοκλήρωση μέχρι την επόμενη ολοκλήρωση· ένας χρόνος βήματος είναι ένα διάστημα, και ο μέσος χρόνος βήματος είναι το μέσο διάστημα

- ω (ωμέγα): χρόνος αναμονής = χρόνος κατά τον οποίο δεν γίνεται πραγματική εργασία, γνωστός και ως χρόνος εκκρεμότητας

- φ (φι): χρόνος εργασίας = χρόνος που αφιερώνεται σε πραγματική εργασία, γνωστός και ως χρόνος επεξεργασίας

![Διάγραμμα: χρόνος παράδοσης τ, χρόνος αναμονής ω, χρόνος εργασίας φ, χρόνος βήματος θ](https://queue-theory.github.io/images/queue-theory-tau-total-time-equals-omega-wait-time-phi-work-time-theta-step-time.svg)

Παραδείγματα:

- τ = 5s σημαίνει ότι ένα στοιχείο εισέρχεται στο σύστημα και εξέρχεται από αυτό 5 δευτερόλεπτα αργότερα.

- ω = 4s σημαίνει ότι ένα στοιχείο περιμένει στην ουρά για 4 δευτερόλεπτα και στη συνέχεια αρχίζει η εργασία.

- φ = 1s σημαίνει ότι ένα στοιχείο χρειάζεται 1 δευτερόλεπτο εργασίας και στη συνέχεια ολοκληρώνεται.

- θ = 1s σημαίνει ότι μεσολαβεί 1 δευτερόλεπτο μεταξύ μιας ολοκλήρωσης και της επόμενης ολοκλήρωσης.

Σχέσεις:

- τ = ω + φ: ο χρόνος παράδοσης είναι ο χρόνος αναμονής συν ο χρόνος εργασίας. Στα παραδείγματα, 5s = 4s + 1s.

- μέσο θ ≈ 1 / χ: σε σταθερή κατάσταση, ο μέσος χρόνος βήματος είναι το αντίστροφο του συνολικού ρυθμού. Ένα μεμονωμένο διάστημα λέει λίγα για τον ρυθμό· ο μέσος όρος πολλών διαστημάτων λέει πολλά. Στα παραδείγματα, αν ο μέσος χρόνος βήματος είναι 1s, τότε χ ≈ 1 στοιχείο ανά δευτερόλεπτο.

### Συμβολισμός Kendall

Ο συμβολισμός Kendall είναι ένας διαφορετικός συμβολισμός της θεωρίας ουρών, που γράφεται ως A/S/c/K/N/D:

- A: η διαδικασία αφίξεων, δηλαδή η κατανομή του χρόνου μεταξύ αφίξεων.

- S: η διαδικασία εξυπηρέτησης, δηλαδή η κατανομή των χρόνων εξυπηρέτησης.

- c: ο αριθμός των εξυπηρετητών.

- K: η χωρητικότητα, δηλαδή ο μέγιστος αριθμός στοιχείων που επιτρέπονται στο σύστημα, σε αναμονή ή υπό εξυπηρέτηση, πριν απορριφθούν οι νέες αφίξεις.

- N: ο πληθυσμός, δηλαδή ο αριθμός των δυνητικών πελατών.

- D: η πειθαρχία, δηλαδή ο τύπος της ουράς, όπως FIFO ή LIFO.

Συνήθη γράμματα για τα A και S:

- M: Μαρκοβιανή, γνωστή και ως χωρίς μνήμη, δηλαδή εκθετικοί χρόνοι, που προκύπτουν από αφίξεις Poisson.

- D: Ντετερμινιστική, δηλαδή σταθεροί χρόνοι.

- G: Γενική, δηλαδή οποιαδήποτε κατανομή.

Όταν τα τρία τελευταία παραλείπονται, οι προεπιλογές είναι K = ∞, N = ∞, D = FIFO. Για παράδειγμα, το «M/M/1» σημαίνει αφίξεις Poisson, εκθετικούς χρόνους εξυπηρέτησης, έναν εξυπηρετητή, απεριόριστη χωρητικότητα, απεριόριστο πληθυσμό και πρώτος μέσα, πρώτος έξω.

Επίσης:

- n: ο αριθμός των στοιχείων στο σύστημα.

## Μαθηματικά των ουρών

Οι μαθηματικές ενότητες χρησιμοποιούν τα σύμβολα των εγχειριδίων, ώστε να μπορείτε να τις συγκρίνετε με άλλες πηγές: το S είναι ο μέσος χρόνος εξυπηρέτησης, δηλαδή το δικό μας φ, και μ = 1 / S είναι η ικανότητα ενός εξυπηρετητή.

### Η καμπύλη χρησιμοποίησης

Το πιο σημαντικό αποτέλεσμα της θεωρίας ουρών: καθώς η χρησιμοποίηση πλησιάζει το 100%, ο χρόνος αναμονής μεγαλώνει χωρίς όριο, και μεγαλώνει ταχύτερα στο τέλος.

Για μια ουρά M/M/1, όπου S είναι ο μέσος χρόνος εξυπηρέτησης:

- Χρόνος παράδοσης τ = S / (1 − ρ)

- Χρόνος αναμονής ω = S × ρ / (1 − ρ)

| Χρησιμοποίηση ρ | Χρόνος παράδοσης τ | Χρόνος αναμονής ω |
| --------------- | ------------------ | ----------------- |
| 50%             | 2 × S              | 1 × S             |
| 70%             | 3,3 × S            | 2,3 × S           |
| 80%             | 5 × S              | 4 × S             |
| 90%             | 10 × S             | 9 × S             |
| 95%             | 20 × S             | 19 × S            |
| 99%             | 100 × S            | 99 × S            |

Παράδειγμα: μια αναθεώρηση κώδικα απαιτεί 1 ώρα εργασίας. Αν οι αναθεωρητές είναι απασχολημένοι κατά 80%, μια αναθεώρηση διαρκεί περίπου 5 ώρες από το αίτημα μέχρι την ολοκλήρωση. Αν οι αναθεωρητές είναι απασχολημένοι κατά 95%, διαρκεί περίπου 20 ώρες, παρόλο που οι αναθεωρητές είναι μόνο 15 ποσοστιαίες μονάδες πιο απασχολημένοι.

Γι' αυτό το «κρατήστε όλους απασχολημένους στο 100%» είναι συνταγή για μεγάλους χρόνους παράδοσης, και γι' αυτό οι [διαπιστώσεις](#διαπιστώσεις) παρακάτω προειδοποιούν κατά του σχεδιασμού για υψηλή χρησιμοποίηση.

### Ο τύπος του Kingman

Ο τύπος του Kingman, γνωστός και ως εξίσωση VUT, προσεγγίζει τον χρόνο αναμονής για μια ουρά με έναν εξυπηρετητή και οποιεσδήποτε κατανομές αφίξεων και εξυπηρέτησης (G/G/1):

- ω ≈ (ρ / (1 − ρ)) × ((ca² + cs²) / 2) × S

Οι τρεις παράγοντες είναι:

- U: παράγοντας χρησιμοποίησης ρ / (1 − ρ), δηλαδή η καμπύλη χρησιμοποίησης παραπάνω.

- V: παράγοντας μεταβλητότητας (ca² + cs²) / 2, όπου ca είναι ο συντελεστής μεταβλητότητας του χρόνου μεταξύ αφίξεων και cs ο συντελεστής μεταβλητότητας των χρόνων εξυπηρέτησης. Ο συντελεστής μεταβλητότητας είναι η τυπική απόκλιση διαιρεμένη με τη μέση τιμή.

- T: παράγοντας χρόνου S, ο μέσος χρόνος εξυπηρέτησης.

Παράδειγμα: για μια ουρά M/M/1, ca = cs = 1, άρα V = 1, και ο τύπος δίνει τον ίδιο χρόνο αναμονής με την καμπύλη χρησιμοποίησης. Αν κάνετε τα στοιχεία εργασίας πιο ομοιόμορφα, για παράδειγμα διασπώντας τα μεγάλα tickets ώστε το cs να πέσει από 1 σε σχεδόν 0, τότε το V πέφτει σε περίπου 0,5, και ο χρόνος αναμονής περίπου υποδιπλασιάζεται με την ίδια χρησιμοποίηση.

Ο τύπος του Kingman δείχνει τους τρεις μοχλούς για τη μείωση του χρόνου αναμονής:

- Μειώστε τη χρησιμοποίηση, για παράδειγμα προσθέτοντας ικανότητα ή περιορίζοντας την εργασία σε εξέλιξη.

- Μειώστε τη μεταβλητότητα, για παράδειγμα με μικρότερες παρτίδες, πιο ομοιόμορφα στοιχεία εργασίας ή πιο ομαλές αφίξεις.

- Μειώστε τον χρόνο εξυπηρέτησης, για παράδειγμα μέσω αυτοματοποίησης.

### Συγκέντρωση και Erlang C

Μία κοινή ουρά που τροφοδοτεί πολλούς εξυπηρετητές είναι καλύτερη από χωριστές ουρές που η καθεμία τροφοδοτεί έναν εξυπηρετητή. Γι' αυτό οι τράπεζες χρησιμοποιούν μία σειρά που τροφοδοτεί πολλά ταμεία, και γι' αυτό μια κοινή ουρά υποστήριξης είναι καλύτερη από ξεχωριστές ουρές ανά εκπρόσωπο.

Παράδειγμα: δύο εξυπηρετητές χρειάζονται ο καθένας 1 ώρα ανά στοιχείο, και τα στοιχεία φτάνουν με ρυθμό 1,6 στοιχεία ανά ώρα συνολικά, άρα η χρησιμοποίηση είναι 80%.

- Χωριστές ουρές: κάθε εξυπηρετητής είναι μια ουρά M/M/1 με 0,8 αφίξεις ανά ώρα, άρα ο χρόνος παράδοσης είναι 1 / (1 − 0,8) = 5 ώρες.

- Κοινή ουρά: οι δύο εξυπηρετητές μοιράζονται μια ουρά M/M/2, άρα ο χρόνος παράδοσης είναι περίπου 2,8 ώρες, δηλαδή περίπου 44% λιγότερο, με τους ίδιους ανθρώπους και την ίδια εργασία.

Ο τύπος Erlang C υπολογίζει την πιθανότητα ένα στοιχείο που φτάνει να πρέπει να περιμένει σε μια ουρά M/M/c, με προσφερόμενο φορτίο a = λ / μ και χρησιμοποίηση ρ = a / c:

- P(wait) = ((aᶜ / c!) / (1 − ρ)) / (Σₖ₌₀ᶜ⁻¹ (aᵏ / k!) + (aᶜ / c!) / (1 − ρ))

- Χρόνος αναμονής ω = P(wait) / (c μ − λ)

Οι ομάδες εξυπηρέτησης πελατών χρησιμοποιούν το Erlang C για να αποφασίσουν πόσους εκπροσώπους χρειάζονται ώστε να πετύχουν έναν στόχο, όπως «το 80% των κλήσεων απαντάται μέσα σε 20 δευτερόλεπτα».

Η συγκέντρωση έχει όρια: λειτουργεί καλύτερα όταν οποιοσδήποτε εξυπηρετητής μπορεί να χειριστεί οποιοδήποτε στοιχείο. Αν τα στοιχεία χρειάζονται ειδικούς, τότε μια κοινή ουρά μπορεί να χρειαστεί κανόνες δρομολόγησης.

## Παρακολούθηση δραστηριοτήτων

### Παραδείγματα δραστηριοτήτων

Ας υποθέσουμε ότι έχουμε κάτι που θέλουμε να παρακολουθούμε, και το ονομάζουμε με ένα γενικό όνομα όπως «Δραστηριότητα», με συντομογραφία «A».

Μπορούμε να χρησιμοποιήσουμε αποτελεσματικά τον συμβολισμό των ουρών για να περιγράψουμε τη δραστηριότητα και τον τρόπο που κινείται μέσα σε μια ουρά.

Παραδείγματα:

- Aκ: πλήθος της δραστηριότητας: πόσα στοιχεία βρίσκονται στην ουρά.

- Aλ: ρυθμός αφίξεων της δραστηριότητας: πόσα στοιχεία εισέρχονται ανά μονάδα χρόνου.

- Aχ: συνολικός ρυθμός της δραστηριότητας: πόσα στοιχεία εξέρχονται από την ουρά ανά μονάδα χρόνου.

- Aα: ρυθμός επιτυχίας της δραστηριότητας: πόσα στοιχεία είναι σωστά ανά μονάδα χρόνου.

- Aβ: ρυθμός αποτυχίας της δραστηριότητας, γνωστός και ως ρυθμός σφαλμάτων: πόσα στοιχεία είναι λανθασμένα ανά μονάδα χρόνου.

- Aμ: ρυθμός εξυπηρέτησης της δραστηριότητας, γνωστός και ως ικανότητα: πόσα στοιχεία μπορεί να ολοκληρώσει ένας εξυπηρετητής ανά μονάδα χρόνου όταν είναι απασχολημένος.

- Aσ: ρυθμός παράλειψης της δραστηριότητας: πόσα στοιχεία εγκαταλείπονται ανά μονάδα χρόνου.

- Aρ: λόγος χρησιμοποίησης της δραστηριότητας: το ποσοστό του διαθέσιμου χρόνου που οι εξυπηρετητές είναι απασχολημένοι, δηλαδή χρόνος απασχόλησης ÷ διαθέσιμος χρόνος, ή λ / (c μ).

- Aε: λόγος σφαλμάτων της δραστηριότητας: πόσα στοιχεία ολοκληρώνονται με σφάλματα σε σχέση με το σύνολο.

- Aτ: χρόνος παράδοσης της δραστηριότητας: πόσος χρόνος μεσολαβεί από το αίτημα μέχρι την ολοκλήρωση.

- Aω: χρόνος αναμονής της δραστηριότητας: πόσος χρόνος μεσολαβεί από το αίτημα μέχρι την έναρξη.

- Aφ: χρόνος εργασίας της δραστηριότητας: πόσος χρόνος μεσολαβεί από την έναρξη μέχρι την ολοκλήρωση.

- Aθ: χρόνος βήματος της δραστηριότητας: πόσος χρόνος μεσολαβεί από μία ολοκλήρωση μέχρι την επόμενη ολοκλήρωση.

### Ο νόμος του Little

Ο νόμος του Little είναι ένα θεώρημα του John Little που ορίζει: ο μακροπρόθεσμος μέσος αριθμός L πελατών σε ένα στάσιμο σύστημα ισούται με τον μακροπρόθεσμο μέσο πραγματικό ρυθμό αφίξεων λ πολλαπλασιασμένο με τον μέσο χρόνο W που περνά ένας πελάτης στο σύστημα.

Παράδειγμα συμβολισμού:

- L: μακροπρόθεσμος μέσος αριθμός πελατών στο σύστημα. Προτιμούμε το κ (κάπα).

- λ: μακροπρόθεσμος μέσος πραγματικός ρυθμός αφίξεων, δηλαδή στοιχεία που πράγματι εισέρχονται στο σύστημα, χωρίς τις αποθαρρύνσεις.

- W: μακροπρόθεσμος μέσος χρόνος που ένα στοιχείο βρίσκεται στο σύστημα. Προτιμούμε το τ (ταυ).

- L = λ W είναι ο νόμος του Little. Προτιμούμε κ = λ τ (κάπα = λάμδα \* ταυ).

Ο νόμος του Little είναι αξιοσημείωτα γενικός: ισχύει ανεξάρτητα από την κατανομή αφίξεων, την κατανομή εξυπηρέτησης, τον αριθμό των εξυπηρετητών ή τον τύπο της ουράς.

Παραδοχές του νόμου του Little:

- Όλες οι μονάδες μέτρησης είναι συνεπείς.

- Το σύστημα είναι σταθερό, δηλαδή ο μέσος ρυθμός αφίξεων ισούται με τον μέσο ρυθμό αναχωρήσεων κατά την περίοδο μέτρησης, και ο αριθμός των στοιχείων είναι περίπου ίδιος στην αρχή και στο τέλος.

- Τα στοιχεία που αποχωρούν νωρίς, για παράδειγμα λόγω αναμονής, είτε μετρώνται με συνέπεια τόσο στο λ όσο και στο τ, είτε εξαιρούνται με συνέπεια και από τα δύο.

Παράδειγμα: μια ομάδα έχει κατά μέσο όρο κ = 20 tickets σε εξέλιξη, και τα tickets φτάνουν με ρυθμό λ = 4 ανά εβδομάδα· σε σταθερή κατάσταση, η ομάδα ολοκληρώνει επίσης χ = 4 ανά εβδομάδα. Άρα το μέσο ticket διαρκεί τ = κ / λ = 5 εβδομάδες. Για να μειώσετε τον χρόνο παράδοσης στο μισό χωρίς να εργάζεστε ταχύτερα, μειώστε την εργασία σε εξέλιξη στο μισό.

### Βασικοί δείκτες απόδοσης (KPIs)

Συνήθως παρακολουθούμε πολλά πράγματα σχετικά με τις δραστηριότητες στην ουρά, και θέλουμε να συνοψίσουμε τα αποτελέσματα επιλέγοντας μια σύντομη λίστα με τους πιο σχετικούς για τα έργα μας.

Έχουμε υλοποιήσει πολλά έργα και πιστεύουμε ότι οι πιο πολύτιμοι συνοπτικοί δείκτες είναι:

- Dτ = Χρόνος παράδοσης. Οι ομάδες προϊόντος μπορεί να λένε «από την ιδέα στον πελάτη» ή «από την ιδέα στην υλοποίηση».

- Dα = Ρυθμός επιτυχίας παράδοσης. Οι ομάδες DevOps μπορεί να λένε «συχνότητα ανάπτυξης» ή «κάνουμε παράδοση X φορές την ημέρα».

- Dε = Λόγος σφαλμάτων παράδοσης. Οι ομάδες ποιότητας μπορεί να λένε «ποσοστό αποτυχίας αλλαγών» ή «ποσοστό επαναφορών».

- Rτ = Χρόνος αποκατάστασης. Οι μηχανικοί αξιοπιστίας τοποθεσιών (SRE) μπορεί να λένε «χρόνος ανάκαμψης από αποτυχημένη ανάπτυξη» ή «μέσος χρόνος αποκατάστασης (MTTR)».

## Μετρικές υπηρεσιών

Χρήσιμοι όροι:

- **Service Level Indicator (SLI), δείκτης επιπέδου υπηρεσίας:** είναι η μετρική (π.χ. 99,9% διαθεσιμότητα)
- **Service Level Objective (SLO), στόχος επιπέδου υπηρεσίας:** ο εσωτερικός στόχος για αυτή τη μετρική (π.χ. στόχος 99,95% διαθεσιμότητα)
- **Service Level Agreement (SLA), συμφωνία επιπέδου υπηρεσίας:** η επίσημη, συμβατική δέσμευση προς τον πελάτη (π.χ. 99,9% διαθεσιμότητα με ποινές αν δεν επιτευχθεί).

### Μέσος χρόνος απόκρισης, επισκευής, ανάκαμψης, επίλυσης

Το MTTR αντιπροσωπεύει τέσσερις διαφορετικές μετρήσεις:

| Μετρική                                         | Εστίαση                   | Μετρά                                           | Αρχή                                              | Τέλος                                             |
| ----------------------------------------------- | ------------------------- | ----------------------------------------------- | ------------------------------------------------- | ------------------------------------------------- |
| **Mean Time To Respond (μέσος χρόνος απόκρισης)** | Αρχική αντίδραση          | Χρόνος για αναγνώριση και έναρξη ενεργειών      | Όταν το συμβάν εντοπίζεται/αναφέρεται             | Όταν η ομάδα αρχίζει να εργάζεται σε αυτό         |
| **Mean Time To Repair (μέσος χρόνος επισκευής)**  | Τεχνική διόρθωση          | Χρόνος για διόρθωση του χαλασμένου στοιχείου    | Όταν αρχίζει η εργασία επισκευής                  | Όταν το στοιχείο διορθώνεται                      |
| **Mean Time To Recover (μέσος χρόνος ανάκαμψης)** | Αποκατάσταση υπηρεσίας    | Χρόνος για πλήρη αποκατάσταση της υπηρεσίας     | Όταν ξεκινά το συμβάν/η διακοπή                   | Όταν η υπηρεσία είναι πλήρως λειτουργική          |
| **Mean Time To Resolve (μέσος χρόνος επίλυσης)**  | Πλήρης επίλυση            | Συνολικός χρόνος από τον εντοπισμό ως το κλείσιμο | Όταν το συμβάν εντοπίζεται                        | Όταν το συμβάν κλείνει οριστικά                   |

**Βασικές διακρίσεις:**

Η **απόκριση** μετρά την ετοιμότητα της ομάδας και την αποτελεσματικότητα των ειδοποιήσεων. Ένας χαμηλός χρόνος απόκρισης σημαίνει ότι οι διαδικασίες παρακολούθησης και εφημερίας σας λειτουργούν καλά, ακόμη κι αν η πραγματική διόρθωση διαρκεί περισσότερο.

Η **επισκευή** είναι αυστηρά τεχνική: πόσος χρόνος χρειάζεται για να διορθωθεί πραγματικά αυτό που χάλασε, από τη στιγμή που εργάζεστε πάνω σε αυτό; Εξαιρεί τον χρόνο εντοπισμού, τη διαλογή (triage) και την επαλήθευση.

Η **ανάκαμψη** αφορά τη διαθεσιμότητα της υπηρεσίας από την οπτική του πελάτη. Το σύστημα μπορεί να έχει «επισκευαστεί» αλλά να μην έχει ακόμη «ανακάμψει», αν πρέπει ακόμη να αποκαταστήσετε δεδομένα, να προθερμάνετε κρυφές μνήμες (caches) ή να επαληθεύσετε τη λειτουργικότητα.

Η **επίλυση** είναι η πιο ολοκληρωμένη: καλύπτει ολόκληρο τον κύκλο ζωής του συμβάντος, από τον πρώτο εντοπισμό έως την επαλήθευση μετά το συμβάν και το κλείσιμο.

Παράδειγμα σεναρίου:

- 2:00 π.μ. — Ξεκινά η διακοπή
- 2:05 π.μ. — Ενεργοποιείται ειδοποίηση, το συμβάν εντοπίζεται
- 2:15 π.μ. — Ο εφημερεύων αναγνωρίζει το συμβάν και αρχίζει την εργασία → Χρόνος απόκρισης: 10 λεπτά (2:05 έως 2:15)
- 2:45 π.μ. — Εντοπίζεται η βασική αιτία, η διόρθωση αναπτύσσεται → Χρόνος επισκευής: 30 λεπτά (2:15 έως 2:45)
- 3:00 π.μ. — Επαληθεύεται ότι η υπηρεσία λειτουργεί για τους χρήστες → Χρόνος ανάκαμψης: 60 λεπτά (2:00 έως 3:00)
- 3:30 π.μ. — Το ticket του συμβάντος κλείνει μετά την επαλήθευση → Χρόνος επίλυσης: 85 λεπτά (2:05 έως 3:30)

Σχετικές μετρικές:

- MTBF (mean time before failure, μέσος χρόνος πριν από αποτυχία)
- MTTF (mean time to failure, μέσος χρόνος μέχρι την αποτυχία)
- MTTA (mean time to acknowledge, μέσος χρόνος μέχρι την αναγνώριση)

### Μετρικές DORA

Οι μετρικές DevOps Research and Assessment (DORA) είναι βασικοί δείκτες απόδοσης (KPIs), πρότυπο του κλάδου, ειδικά για ομάδες DevOps στη μηχανική λογισμικού. Δείτε [dora.dev](https://dora.dev/guides/dora-metrics/).

Το DORA χρησιμοποιεί πλέον πέντε μετρικές, σε δύο ομάδες.

Μετρικές διεκπεραίωσης:

- **Change Lead Time (χρόνος παράδοσης αλλαγής)** - Χρόνος για την υλοποίηση, τον έλεγχο και την παράδοση κώδικα για μια λειτουργία (μετριέται από το commit έως την ανάπτυξη στην παραγωγή). Να είστε συγκεκριμένοι ως προς το τι εννοείτε με αρχή και τέλος. Για παράδειγμα, ορισμένες ομάδες προτιμούν να μετρούν από τη στιγμή που ένας προγραμματιστής αρχίζει να εργάζεται σε ένα ticket μέχρι τη στιγμή που ο προγραμματιστής στέλνει την εργασία σε μια διαδικασία συνεχούς ενοποίησης· αυτή η προσέγγιση τείνει να είναι πιο αποτελεσματική για τη μέτρηση της παραγωγικότητας του ατόμου.

- **Deployment Frequency (συχνότητα ανάπτυξης)** - Αριθμός αναπτύξεων σε δεδομένο χρονικό διάστημα. Να είστε συγκεκριμένοι ως προς το τι εννοείτε με ανάπτυξη και πώς παρακολουθείτε τη συχνότητα. Για παράδειγμα, ορισμένες ομάδες κάνουν ανάπτυξη σε ένα σύνολο διακομιστών παραγωγής και παρακολουθούν την πλήρη διάθεση, ενώ άλλες ομάδες κάνουν ανάπτυξη σε έναν μόνο διακομιστή ελέγχου αποδοχής από τον χρήστη (UAT) και παρακολουθούν πότε ο υπεύθυνος έργου στέλνει ανακοίνωση με email στους χρήστες για να ξεκινήσουν τις δοκιμές.

- **Failed Deployment Recovery Time (χρόνος ανάκαμψης από αποτυχημένη ανάπτυξη)** - Χρόνος που χρειάζεται για ανάκαμψη από μια ανάπτυξη που προκαλεί αποτυχία στην παραγωγή. Παλαιότερα ονομαζόταν Mean Time to Recovery (MTTR) ή Time to Restore Service. Να είστε συγκεκριμένοι ως προς το τι εννοείτε με ανάκαμψη. Για παράδειγμα, ορισμένες ομάδες θεωρούν ως ανάκαμψη την πλήρη επίλυση, δηλαδή τον συνολικό χρόνο από τον εντοπισμό ενός συμβάντος μέχρι το οριστικό κλείσιμό του· αυτή η προσέγγιση περιγράφεται καλύτερα ως Mean Time To Resolve.

Μετρικές αστάθειας:

- **Change Failure Rate (ποσοστό αποτυχίας αλλαγών)** - Ποσοστό των αναπτύξεων που προκαλούν αποτυχία στην παραγωγή και χρειάζονται άμεση αποκατάσταση, όπως επαναφορά (rollback) ή επείγουσα διόρθωση (hotfix). Να είστε συγκεκριμένοι ως προς το τι εννοείτε με αποτυχία. Για παράδειγμα, ορισμένες ομάδες μετρούν επίσης ως αποτυχία την περίπτωση όπου αρχίζουν ένα ticket εργασίας και στη συνέχεια διαπιστώνουν ότι το ticket δεν έχει αρκετές πληροφορίες για να προχωρήσουν, οπότε η ομάδα επιστρέφει το ticket στην ομάδα προδιαγραφών.

- **Deployment Rework Rate (ποσοστό επανεργασίας αναπτύξεων)** - Ποσοστό των αναπτύξεων που δεν είναι προγραμματισμένες, όπως για τη διόρθωση ενός συμβάντος παραγωγής. Πρόκειται για τις μη προγραμματισμένες αναπτύξεις διαιρεμένες με το σύνολο των αναπτύξεων. Το DORA πρόσθεσε αυτή τη μετρική το 2024.

Παλαιότερες αναφορές του DORA εξέταζαν επίσης την **αξιοπιστία (Reliability)** ως μετρική λειτουργικής απόδοσης: μια ευρύτερη, συχνά ποιοτική, αξιολόγηση της συνέπειας της υπηρεσίας, όπως η διαθεσιμότητα, ο χρόνος λειτουργίας, η καθυστέρηση, η ακρίβεια και οι στόχοι επιπέδου υπηρεσίας. Η αξιοπιστία βοηθά να φανεί ότι η υψηλή ταχύτητα δεν έρχεται σε βάρος της ικανότητας του συστήματος.

## Ουρά ουρών

Η θεωρία ουρών επεκτείνεται εύκολα σε μια ουρά ουρών, όπως μια διαδικασία ανώτερου επιπέδου που περιέχει στάδια, φάσεις ή πύλες κατώτερου επιπέδου.

### Ουρά ουρών Double Diamond

Για παράδειγμα, εξετάστε το μοντέλο διαδικασίας καινοτομίας «Double Diamond» (διπλό διαμάντι), το οποίο ορίζει τέσσερα στάδια:

1. Ανακάλυψη: Κατανοήστε το ζήτημα αντί απλώς να υποθέτετε τι είναι.
2. Ορισμός: Με τη γνώση από τη φάση της ανακάλυψης, ορίστε την πρόκληση.
3. Ανάπτυξη: Δώστε διαφορετικές απαντήσεις στο σαφώς ορισμένο πρόβλημα.
4. Παράδοση: Δοκιμάστε διαφορετικές λύσεις σε μικρή κλίμακα και στη συνέχεια βελτιώστε τις.

Η θεωρία ουρών μπορεί να το μοντελοποιήσει ως μία ουρά διαδικασίας που περιέχει τέσσερις ουρές σταδίων:

- Ο ρυθμός αφίξεων της διαδικασίας είναι ο ρυθμός αφίξεων του σταδίου 1.
- Ο ρυθμός επιτυχίας της διαδικασίας είναι ο ρυθμός επιτυχίας του σταδίου 4.
- Το πλήθος σφαλμάτων της διαδικασίας είναι το άθροισμα των πληθών σφαλμάτων των σταδίων.
- Το πλήθος παραλείψεων της διαδικασίας είναι το άθροισμα των πληθών παραλείψεων των σταδίων.
- Ο χρόνος παράδοσης της διαδικασίας είναι το άθροισμα των χρόνων παράδοσης των σταδίων.
- Η μέγιστη διεκπεραίωση της διαδικασίας είναι η διεκπεραίωση του πιο αργού σταδίου, γνωστού και ως σημείο συμφόρησης.

### Ουρά ουρών τύπου χοάνης

Στην πρακτική μας εργασία, χρησιμοποιούμε συχνά τη λέξη «χοάνη» (funnel) για να περιγράψουμε χαλαρά μια ουρά ουρών που τείνει να μειώνει το πλήθος των στοιχείων σε κάθε στάδιο:

- Ουρά πρόσληψης με στάδιο προσέγγισης υποψηφίων, στάδιο συνεντεύξεων και στάδιο προσφοράς. Για αυτό το είδος ουράς, στοχεύουμε να μεγιστοποιήσουμε τον ρυθμό αφίξεων του σταδίου 1, δηλαδή να αυξήσουμε την προσέγγισή μας, για παράδειγμα μέσω προωθητικών ενεργειών.

- Ουρά αγοράς με στάδιο αναζήτησης από τον πελάτη, στάδιο καλαθιού αγορών και στάδιο πληρωμής. Για αυτό το είδος ουράς, στοχεύουμε να ελαχιστοποιήσουμε τον ρυθμό παράλειψης του σταδίου 2, δηλαδή να μειώσουμε την εγκατάλειψη καλαθιού, για παράδειγμα μέσω υπενθυμίσεων.

- Ουρά προγραμματισμού με στάδιο ενοποίησης, στάδιο αποδοχής από τον χρήστη και στάδιο διάθεσης στην παραγωγή. Για αυτό το είδος ουράς, στοχεύουμε να ελαχιστοποιήσουμε τον ρυθμό σφαλμάτων του σταδίου διάθεσης στην παραγωγή, για παράδειγμα μέσω τηλεμετρίας canary.

## Διαπιστώσεις

Επτά διαπιστώσεις για τη θεωρία ουρών, από τον Bob Wescott, συγγραφέα του «The Every Computer Performance Book» (δείτε επίσης [τη σύνοψη του Kottke](https://kottke.org/19/01/its-time-for-some-queueing-theory)):

1. Όσο πιο αργό είναι το κέντρο εξυπηρέτησης, τόσο χαμηλότερη μέγιστη χρησιμοποίηση πρέπει να προβλέπετε για το φορτίο αιχμής.

2. Είναι πολύ δύσκολο να χρησιμοποιήσετε το τελευταίο 15% οποιουδήποτε πράγματος.

3. Όσο πιο κοντά βρίσκεστε στο όριο, τόσο υψηλότερο είναι το τίμημα αν κάνετε λάθος.

4. Οι αυξήσεις του χρόνου απόκρισης περιορίζονται από τον αριθμό εκείνων που μπορούν να περιμένουν.

5. Θυμηθείτε ότι πρόκειται για μέσο όρο, όχι για μέγιστο.

6. Υπάρχει ένα ανθρώπινο φαινόμενο άρνησης σε πολλαπλά κέντρα εξυπηρέτησης.

7. Παρουσιάστε τις μικρές βελτιώσεις με τον καλύτερο δυνατό τρόπο.
